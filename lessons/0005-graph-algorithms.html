1. Exploring: BFS and DFS

  • BFS (breadth-first): visit the start, then all its neighbours, then all of their neighbours, level by level. Uses a queue. It finds the path with the fewest edges.
  • DFS (depth-first): go as deep as possible along one path, then backtrack. Uses a stack (or recursion).
  • Both cost O(V + E) with adjacency lists.

2. Minimum spanning tree (MST)

A spanning tree connects all V vertices using exactly V − 1 edges and no cycle. The minimum spanning tree is the one with the smallest total edge weight.

Kruskal's algorithm: pick the cheapest edge that doesn't make a cycle

  1. Sort all edges by weight.
  2. Take the next cheapest edge; if it joins two different components, keep it; otherwise (it would form a cycle) skip it.
  3. Stop when you have V − 1 edges.
Worked example

Vertices A, B, C, D. Edges: A–B 1, B–C 2, A–C 3, C–D 4, B–D 5. Sorted: 1 (A–B) keep; 2 (B–C) keep; 3 (A–C) would close the cycle A–B–C, skip; 4 (C–D) keep. We now have 3 edges for 4 vertices: done. Total weight = 1 + 2 + 4 = 7, number of edges = 3.

Prim's algorithm: grow one tree

Start from any vertex. Repeatedly add the cheapest edge that connects the current tree to a new vertex. Same answer weight as Kruskal.

Cost: Kruskal O(E log E); Prim O(E log V) with a heap.

3. Shortest paths from one source

Dijkstra: always finalise the closest unvisited vertex

  1. Set distance of the start to 0 and all others to ∞.
  2. Pick the unvisited vertex with the smallest distance; mark it final.
  3. For each neighbour, see if going through this vertex gives a shorter distance, and update.
  4. Repeat until all are final.
Worked example

Edges: S–A 4, S–B 1, B–A 2, A–T 1, B–T 5. Start S. Distances: S=0, A=4, B=1, T=∞. Pick B (1): A becomes min(4, 1+2) = 3, T = 1+5 = 6. Pick A (3): T = min(6, 3+1) = 4. Pick T. Shortest S→T = 4 via S–B–A–T.

Dijkstra fails with negative edge weights because it assumes a finalised vertex can never be improved. Use Bellman–Ford instead.

Bellman–Ford: relax every edge V − 1 times

Handles negative edges and can detect a negative-weight cycle (if an edge can still be relaxed on the V-th pass). Cost O(V·E).

4. All-pairs shortest paths: Floyd–Warshall

Keep a table dist[i][j]. For each possible intermediate vertex k, check whether going i → k → j is shorter than the current i → j. Three nested loops: O(V³). It is an example of dynamic programming. Use it when the question says "shortest paths between all pairs".

5. Greedy method and Huffman coding

Greedy algorithm: at each step make the choice that looks best right now (a local optimum), and never reconsider. It does not try all possibilities. It works only when the problem has a structure that makes local choices safe. Kruskal, Prim, Dijkstra, Huffman and fractional knapsack are greedy.

Huffman coding compresses data by giving shorter bit codes to more frequent symbols. It works on the frequencies of the input symbols: repeatedly merge the two least frequent items into one node whose frequency is their sum, until one tree remains. Left edge = 0, right edge = 1.

Worked example

Frequencies: A 5, B 9, C 12, D 13. Merge A and B (5+9) → node 14. Now the smallest two are C 12 and D 13 → node 25. Merge 14 and 25 → 39. Codes: C = 00, D = 01, A = 100, B = 101. The most frequent symbols (C, D) get the shortest codes.

Greedy vs dynamic programming

Greedy: one choice per step, no looking back. Dynamic programming: solve small subproblems, store the answers, and combine them (Floyd–Warshall, 0/1 knapsack, multistage graph). Use DP when the greedy choice can be wrong.

The multistage graph problem asks for the cheapest path through a graph arranged in stages (source → stage 1 → … → destination) and is solved by DP.

Match: (A) Floyd Warshall (B) Dijkstra (C) Kruskal's (D) Bellman Ford with (i) shortest path between two vertices, (ii) single source shortest path, (iii) minimum spanning tree, (iv) solving all-pair shortest path. Which option gives the correct set of pairs?

Two matches are certain: Floyd–Warshall = all-pairs (iv) and Kruskal = MST (iii). Only the second option contains both of them, so it is the answer. Its pairing of Dijkstra with (i) and Bellman–Ford with (ii) is just how the question was written; both really solve the single-source problem.
