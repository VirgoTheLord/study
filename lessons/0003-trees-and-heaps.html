3 · Trees, BSTs, Heaps and Expressions

Module A · Data structuresAsked in 2023 and 2025 Traversals, binary search trees, priority queues, postfix and prefix.

Start here: what is a tree?

A tree is a way to store things in a hierarchy, like a family tree or folders on a computer. There is one starting node, the root. Every node can have children. A node with no children is a leaf. The number of edges from the root down to a node is its depth; the longest such path is the tree's height. A tree with n nodes always has exactly n − 1 edges.

A binary tree is a tree where every node has at most two children, called left and right.

Traversals: three ways to visit every node

A traversal is a rule for the order in which you visit nodes. The names tell you when the root is visited:

NameOrder
PreorderRoot, then left subtree, then right subtree
InorderLeft subtree, then root, then right subtree
PostorderLeft subtree, then right subtree, then root
Worked example: all three traversals

Preorder: visit 10, then go left: visit 5, then its left 1, its right 7; then right of 10: visit 40, then 50. Result: 10 5 1 7 40 50.

Inorder: for 10, first do the whole left subtree (inorder of 5: 1, 5, 7), then 10, then right subtree (40, 50). Result: 1 5 7 10 40 50.

Postorder: left subtree of 10 postorder = 1 7 5; right subtree = 50 40; then 10. Result: 1 7 5 50 40 10.

Trick for the exam: write the rule down, apply it recursively, and always finish a whole subtree before moving on.

Binary search trees (BST)

BST rule: for every node, everything in its left subtree is smaller, and everything in its right subtree is larger.

  • Search: start at the root; go left if the target is smaller, right if larger. Cost = height of the tree (log n if balanced, n if it degenerates into a line).
  • Insert: search for where it would be, and attach it there.
  • Inorder traversal of a BST is the sorted list. (Look at the example above: 1 5 7 10 40 50.) This is the most useful fact.
  • Delete: a leaf is removed directly; a node with one child is replaced by that child; a node with two children is replaced by its inorder successor (smallest in the right subtree) or predecessor.
  • Inorder predecessor of a node = the next smaller value. Go to its left child, then keep going right as far as possible. If there is no left child, it's the closest ancestor you reached by turning right.
Worked example: rebuild a BST from its preorder

Preorder is 10, 5, 1, 7, 40, 50. The first element, 10, is the root. In preorder the next values smaller than 10 (5, 1, 7) form the left subtree, and the remaining larger ones (40, 50) form the right. Repeat inside each: left subtree has root 5, with 1 (smaller → left) and 7 (larger → right). Right subtree has root 40 with 50 as its right child. That gives exactly the tree drawn above. Its postorder is 1 7 5 50 40 10.

Any binary tree is determined by its preorder together with its inorder (or postorder with inorder). Preorder alone is enough only for a BST, because the BST rule tells you where each value belongs.

Heaps and priority queues

A priority queue is a waiting line where the item with the highest priority is served first, not the one who arrived first. Items can be inserted at any priority, and the item removed is whichever has the highest priority. (So it is not a simple front/back queue.)

The standard implementation is a binary heap: a complete binary tree (all levels full except possibly the last, filled left to right) with the heap rule: in a max-heap each parent is ≥ its children (a min-heap is the opposite). A heap is stored in a plain array: the children of position i are at 2i and 2i+1.

  • Insert: put the new item at the end, then "bubble up" by swapping with its parent while it is bigger. Cost O(log n).
  • Delete the top: move the last item to the root, then "sift down" by swapping with the larger child. O(log n).
  • Build a heap from n items: O(n).

Expressions: infix, prefix, postfix

We normally write infix: A + B, operator in the middle. In prefix (Polish notation) the operator goes first: + A B. In postfix (reverse Polish) it goes last: A B +. Postfix and prefix need no brackets because the order already says what to do first.

Worked example: A*B + C*D to postfix

Multiplication goes before addition, so group as (A*B) + (C*D). Convert each part: A B *, and C D *. Then put + after both: A B * C D * +. The prefix form is + * A B * C D.

Worked example: evaluate a postfix expression with a stack

Scan left to right. A number → push it. An operator → pop two numbers, apply, push the result. For 2 3 4 * +: push 2, push 3, push 4; see *: pop 4 and 3, push 12; see +: pop 12 and 2, push 14. Answer: 14.

Worked example: evaluate a prefix expression

Scan right to left using the same stack rule (first popped is the left operand). For + 3 * 4 5: push 5, push 4, see *: 4*5 = 20; push 3; see +: 3+20 = 23.

Other quick facts

  • Diameter of a binary tree (longest path between two nodes) can be found in O(n) with one traversal: at each node, the longest path through it is (height of left) + (height of right) + 1 nodes.
  • Pointer arithmetic (C/C++): adding 1 to a pointer moves it by the size of its type. If an int is 2 bytes and p = 200, then p + 3 = 200 + 3 × 2 = 206.

Evaluating a polynomial with the fewest operations (Horner's rule)

To evaluate aₙxⁿ + … + a₁x + a₀ cheaply, nest it: ((aₙx + aₙ₋₁)x + …)x + a₀. A degree-n polynomial then takes n multiplications and n additions, instead of computing every power separately. When some terms are missing, factor smartly: 8z³ + 3z + 12 = z(8z² + 3) + 12 needs z² (1 multiplication), 8·z² (1), +3 (1), ×z (1), +12 (1) = 5 operations. (The polynomial in 2023 Q5 was garbled in the PDF text; if it is this one, the answer is 5. Apply the same nesting method to whatever the printed polynomial is.)

Pointers and arrays in C/C++: what can crash a program

int *ptr = new int[4]; reserves room for four ints: valid positions are ptr[0] to ptr[3]. Then: ptr++ and ptr += 3 just move the pointer inside the block, which is legal (but you must remember the original address to free it later). ptr = nullptr leaks the memory but does not itself crash. ptr[4] = 0x16 writes one element past the end: this is out-of-bounds access, undefined behaviour that can corrupt the heap and crash the program. Other classic C/C++ memory errors: buffer overflow, using freed memory (dangling pointer), freeing the same memory twice, dereferencing a null pointer.
