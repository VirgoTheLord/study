12 · Memory Management

Module C · Operating systemsAsked in 2023 and 2025 Allocation, paging, segmentation, virtual memory, page replacement.

Start here

A program must be in main memory (RAM) to run. The OS must decide where to put each process, keep processes out of each other's memory, and cope when the programs together need more memory than exists. Every idea in this lesson is an answer to one of those problems.

  • A logical (virtual) address is what the program uses. A physical address is a real RAM location. A hardware unit, the MMU, translates one to the other.

Contiguous allocation and fragmentation

The simplest scheme gives each process one continuous block of memory. When processes come and go, free memory breaks into scattered holes. Choosing which hole to give to a new process:

StrategyRule
First fitThe first hole that is big enough (fast)
Next fitLike first fit, but start searching from where the last search ended
Best fitThe smallest hole that is big enough (leaves tiny useless leftovers)
Worst fitThe largest hole (leaves large leftovers)

Two kinds of waste: internal fragmentation (wasted space inside an allocated block, e.g. a fixed-size block bigger than needed) and external fragmentation (enough total free memory, but scattered in pieces too small to use). Compaction shuffles processes together to merge the holes.

Exam note: 2023 asked which heap-allocation strategy best exploits spatial locality (options: best, first, next, last fit). I could not confirm the official answer, so I am not claiming one. The reasoning to apply: a strategy that keeps handing out memory from nearby addresses keeps related data close together, and next fit continues from the previous allocation point while first fit always restarts from the low end. Paging

Paging removes external fragmentation. Physical memory is divided into equal frames; a process's logical memory is divided into pages of the same size. Any page can go into any free frame. A page table per process maps page number → frame number.

Worked example: address translation

Page size 1 KB (1024 bytes). Logical address 2500. Page number = 2500 ÷ 1024 = 2 (integer part), offset = 2500 mod 1024 = 452. Suppose the page table says page 2 is in frame 7. Physical address = 7 × 1024 + 452 = 7620.

In binary terms: a logical address is split into page number | offset; the physical address is frame number | offset; the offset is unchanged.

The TLB

The page table lives in memory, so each access would cost two memory reads (one for the table, one for the data). The TLB (translation lookaside buffer) is a small fast cache of recent translations. Effective access time = hit ratio × (TLB time + memory time) + (1 − hit ratio) × (TLB time + 2 × memory time).

Worked example

TLB 10 ns, memory 100 ns, hit ratio 90%. EAT = 0.9 × (10 + 100) + 0.1 × (10 + 200) = 99 + 21 = 120 ns.

Segmentation

Programmers think in logical units: the code, the data, the stack, the heap. Segmentation splits a process into such variable-sized segments. An address is a pair (segment number, offset). A segment table holds each segment's base and limit; if the offset exceeds the limit the hardware traps. Segmentation can suffer external fragmentation. The compiler creates the segments, and the loader assigns them segment numbers when the program is loaded.

Virtual memory and demand paging

With virtual memory, a process can be larger than RAM: only the pages currently needed are kept in frames; the rest stay on disk. This is demand paging: a page is brought in only when it is touched. A reference to a page not in memory causes a page fault:

  1. The hardware traps to the OS.
  2. The OS finds the page on disk.
  3. It finds a free frame (or evicts a page, see below).
  4. It reads the page from disk into the frame.
  5. It updates the page table and restarts the instruction.

A page fault is very slow (disk, milliseconds), so even a tiny fault rate hurts: with memory 200 ns, fault service 8 ms and fault rate p = 1/1000, EAT = (1 − p) × 200 + p × 8,000,000 ns ≈ 8200 ns, 40 times slower. Thrashing is when the system spends more time swapping pages than doing useful work.

Page replacement algorithms

When memory is full and a fault occurs, the OS must evict a page. Goal: fewest page faults on a given reference string.

AlgorithmEvict…
FIFOThe page that has been in memory longest
LRUThe page not used for the longest time (look back)
OptimalThe page whose next use is farthest in the future (look ahead); fewest faults possible but impossible to implement in practice; used as a benchmark
