8 · How a Compiler Works

Module B · CompilersAsked in 2023 and 2025 The phases, what each one produces, and the tools around it.

Start here

A compiler translates a program written in a high-level language (C, Java) into something a machine can run. The computer cannot understand "position = initial + rate * 60" directly, so the compiler works in stages, each stage transforming the program into a form closer to machine code. Think of an assembly line: raw text goes in one end, machine code comes out the other.

Walking one statement through the pipeline

Source: position = initial + rate * 60

1. Lexical analysis (the scanner)

Reads the raw characters and groups them into tokens, the "words" of the language. A lexeme is the actual text (rate); the token is its category (identifier). Result: id1 = id2 + id3 * 60. Whitespace and comments are discarded. The patterns for tokens are written as regular expressions and recognised by finite automata (lessons 6). It also enters names into the symbol table.

2. Syntax analysis (the parser)

Takes the stream of tokens and checks they follow the grammar, building a parse tree (or syntax tree) showing structure: here, * binds tighter than +, so rate*60 is a subtree. Errors like a missing bracket are caught here. The parser receives the tokenised output from the lexical analyser.

3. Semantic analysis

Checks meaning: are variables declared? Do the types match? Here, if id2 and id3 are floating-point and 60 is an integer, the compiler inserts a conversion: inttofloat(60).

4. Intermediate code generation

Produces a simple machine-independent form, usually three-address code (each instruction has at most three operands):
t1 = inttofloat(60)
t2 = id3 * t1
t3 = id2 + t2
id1 = t3

5. Code optimisation

Rewrites the intermediate code to run faster or use less memory without changing what it does: t1 = id3 * 60.0, id1 = id2 + t1. Typical tricks: constant folding (compute 2*3 at compile time), common subexpression elimination, dead-code removal, moving unchanging code out of loops, replacing multiplication by shifts (strength reduction).

6. Code generation

Turns the optimised intermediate code into machine instructions for the target CPU, choosing registers.

The first three phases (up to semantic analysis) are the front end, which depends on the source language. The last two or three are the back end, which depends on the target machine. This split is why one back end can serve several languages.

The whole toolchain

Source → Preprocessor → Compiler → Assembly → Assembler → Object code → Linker → Loader → Running program

  • Preprocessor: expands macros and #include.
  • Assembler: turns assembly into relocatable machine code (object file).
  • Linker: combines object files and libraries into one executable, resolving references between them.
  • Loader: places the executable into memory to run.

Tools that generate compilers

  • lex (or flex): you give it regular expressions for tokens; it generates a lexical analyser.
  • yacc (or bison): you give it a grammar in BNF-like notation; it generates a parser.
  • gdb is a debugger; ed is a text editor: neither generates parsers.

Interpreters and virtual machines

An interpreter runs code directly, line by line, without producing a separate machine-code file. Java does both: javac compiles source to bytecode, which is hardware independent; the JVM (Java Virtual Machine) then runs that bytecode on a specific machine. The bytecode is the input to the VM, not a part of the VM. The JVM itself is platform-specific, which is what lets the same bytecode run everywhere.

Check yourself

ISRO 2023 · Q10

Which sequence below best describes the order in which the phases of a compiler typically work?

Lexical → syntax → semantic → intermediate code generation → code optimisation. Optimisation works on the intermediate code, so it must come after that code exists.
ISRO 2025 · Q30

Which compiler phase receives tokenized output?

The lexical analyser produces tokens; the parser consumes them.
ISRO 2025 · Q31

Which one of the following tools generates a parser from BNF notation?

yacc ("yet another compiler compiler") makes parsers; lex makes scanners.
ISRO 2025 · Q29

Which one of the following is true for a Virtual Machine like JVM?

The JVM gives programs a hardware-independent execution environment. Bytecode is what the VM runs, not part of the VM itself; linking is a separate toolchain job.
