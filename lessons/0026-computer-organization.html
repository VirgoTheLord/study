26 · Computer Organization: CPU, Pipelining, Interrupts, Cache

Module G · Computer architectureAsked in 2023 How a processor executes instructions and how it is made fast.

Start here: the parts of a computer

A computer has a CPU (the processor), memory and input/output devices, joined by buses (shared wires for addresses, data and control). The CPU has an ALU (arithmetic and logic unit that computes), a control unit (directs everything), and registers (tiny, very fast storage), such as the program counter (PC) holding the address of the next instruction, the instruction register (IR), and the accumulator.

The instruction cycle

The CPU repeats forever: Fetch the instruction from memory at the address in PC (and increment PC) → Decode it to see what it means → Execute it (compute, read/write memory) → store the result. The elementary operations performed on data held in registers (like "copy R1 into R2", "add R1 and R2") are called micro-operations; each instruction is built from a sequence of them.

Instruction set architecture (ISA) is the contract between software and hardware: the instructions, registers and addressing modes the programmer sees. Addressing modes say how an operand is found: immediate (value in the instruction), direct (address in the instruction), indirect (address of the address), register, indexed.

Pipelining

Without pipelining, the CPU finishes one instruction completely before starting the next, like a laundry where you wash, dry and fold one load at a time. Pipelining overlaps the stages: while one instruction is being executed, the next is being decoded and the one after is being fetched, just as you can put load 2 in the washer while load 1 is in the dryer.

  • With k stages and a long run of instructions, the ideal speed-up approaches k. To run n instructions: time ≈ (k + n − 1) cycles instead of n × k.
  • An instruction pipeline can be implemented with FIFO buffers between stages (first in, first out keeps the instructions in order); a stack (LIFO) would reverse the order.
  • Hazards stop the ideal flow: structural (two stages need the same hardware), data (an instruction needs a result not yet computed), control (a branch changes what comes next).

Faster still: superscalar

A superscalar processor has several execution units and can issue and finish more than one instruction per clock cycle. For a given number of instructions it gives the fastest execution among the choices in the exam (ISA is just the interface, not a speed technique; "ANSA" is not a processor architecture type).

Interrupts

An interrupt lets a device (keyboard, disk) get the CPU's attention. The CPU finishes its current instruction, saves its state, runs a short interrupt service routine, and then resumes. How does the CPU find the right routine?

  • Non-vectored: all interrupts go to one fixed address and software works out the source.
  • Vectored interrupt: the interrupting device itself supplies the address (or an index into a table of addresses, the interrupt vector) of its service routine, so the CPU jumps straight to the right place.

DMA (direct memory access) lets an I/O device transfer blocks of data to or from memory without involving the CPU in each byte.

Memory hierarchy and cache

Fast memory is small and expensive; big memory is slow. So computers stack them: registers → cache → main memory → disk. A cache keeps copies of recently used data close to the CPU. A hit means the data was in the cache; a miss means it had to come from memory. This works because of locality: programs reuse recent data (temporal locality) and touch nearby addresses (spatial locality).

Average memory access time = h × t_cache + (1 − h) × t_memory, where h is the hit ratio. Example: h = 0.9, cache 5 ns, memory 100 ns: 0.9 × 5 + 0.1 × 100 = 14.5 ns.

Cache mapping: direct-mapped (each block has exactly one cache line; simple, more conflicts), fully associative (any block anywhere; flexible, costly), set-associative (a compromise).
