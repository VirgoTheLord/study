2 · Sorting

Module A · AlgorithmsAsked in 2023 and 2025 How each sorting method works, and how to recognise one from a partly sorted array.

Start here

Sorting means arranging items in order. There are many methods, and the exam asks two things: (1) how fast is it in best, average and worst case, and (2) given an array after a few steps, which method was used. To answer (2) you must know exactly what one step of each method does. We will use one array throughout: [10, 5, 16, 2, 8, 9].

The three slow, simple methods (O(n²))

Bubble sort: swap neighbours that are out of order

Walk through the array comparing each pair of neighbours; swap if the left one is bigger. After one full pass the largest element has "bubbled" to the end. Repeat for the rest.

Telltale sign: after k passes, the last k places hold the k largest values in order.

Selection sort: pick the smallest, put it at the front

Find the minimum of the whole array and swap it into position 1. Then find the minimum of the rest and swap it into position 2, and so on.

Telltale sign: after k passes, the first k places hold the k smallest values, and the rest look scrambled because of the swaps.

Insertion sort: how you sort playing cards

Keep the left part sorted. Take the next element and slide it left into its correct place within the sorted part.

StepArray (sorted part in bold)
start10 5 16 2 8 9
1: insert 55 10 16 2 8 9
2: insert 165 10 16 2 8 9
3: insert 22 5 10 16 8 9

Telltale sign: after k steps, the first k+1 elements are sorted among themselves, and the rest of the array is untouched, exactly as in the input.

Identify the sort (this is a 2025 question)

Input {10, 5, 16, 2, 8, 9} gives {2, 5, 10, 16, 8, 9} after three iterations. Check each method against the tables above: after 3 bubble passes we would have the 3 largest at the end (not true). After 3 selection passes we would have 2 5 8 at the front (not true). After 3 insertion steps, the first four are sorted and 8 9 are untouched: 2 5 10 16 | 8 9 ✓. Insertion sort.

The fast methods (O(n log n))

Merge sort: split, sort halves, merge

Split the array in half, sort each half the same way (recursion), then merge two sorted halves by repeatedly taking the smaller front element. Always n log n. Needs extra space of size n. It is stable (equal items keep their original order).

Quick sort: pick a pivot, partition around it

Choose a pivot. Rearrange so everything smaller is to its left and everything larger to its right. The pivot is now in its final place. Sort the two sides the same way. Average n log n, but worst case n² when the pivot is always the smallest or largest (e.g. picking the first element on an already sorted array).

Heap sort: use a heap

Build a max-heap (see lesson 3), then repeatedly swap the top (largest) to the end and repair the heap. Worst case O(n log n) always, sorts in place, not stable.

Sorting without comparing: counting and radix

Counting sort counts how many times each value appears and writes the values out in order; fast when the value range k is small: O(n + k). Radix sort sorts numbers one digit at a time, from the least significant digit to the most, using a stable sort for each digit. For d-digit numbers it takes d passes: O(d·(n + k)).

Radix sort on 170, 45, 75, 90, 802

Sort by units digit: 170, 90, 802, 45, 75. Then by tens digit: 802, 45, 170, 75, 90. Then by hundreds digit: 045, 075, 090, 170, 802. Done in 3 passes with no element-to-element comparisons.

A question to be careful with. 2023 Q25 asked for the "maximum number of comparisons" to radix-sort 6 three-digit numbers (options 120, 180, 210, 360). Radix sort does not compare elements with each other; it makes d passes (here 3), each pass over all n items. I could not derive which of those numbers the official key uses, so do not rely on my guess: check your key. What you do need to know is the cost, O(d·(n + k)).

Check yourself

ISRO 2025 · Q7

Which sorting technique was applied to the input array {10, 5, 16, 2, 8, 9} to give {2, 5, 10, 16, 8, 9} after three iterations?

Insertion sort. The first four elements (2 5 10 16) are sorted and the last two (8, 9) are exactly as in the input. See the table above: bubble would push large values to the end, selection would put the three smallest first.
ISRO 2023 · Q29

Worst case time complexity of heap sort for n elements is

Building the heap costs O(n); each of the n extractions costs O(log n). Total O(n log n), in every case.
Practice (ISRO style, written by me)

Which sorting algorithm has the best running time when the input is already nearly sorted?

Insertion sort does almost no shifting when elements are near their places, so it approaches O(n). Selection sort is always n². Quick sort with a first-element pivot is bad on sorted input.
