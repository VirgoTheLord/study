1 · Big-O and Growth Rates

Module A · AlgorithmsAsked in 2023 and 2025 How to say "how slow is this program?" in one line.

Start here: why do we need this?

Suppose two people write a program to find a name in a list. Both programs work. Which one is better? You cannot just time them, because the timing depends on the computer. So instead we count how many steps the program takes as the input grows. If the list has n names, does the work grow like n? Like n × n? Like log n? That growth pattern is what Big-O notation describes.

Big-O: O(f(n)) means "the running time grows no faster than f(n) once n is large, ignoring constant factors." It is an upper bound. People also use Ω (omega) for a lower bound and Θ (theta) for "exactly this growth, bounded above and below."

Step 1: count the steps

Look at the loops. Each pattern has a standard cost:

Code shapeStepsWhy
for i in 1..n: do somethingnThe body runs n times
for i in 1..n: for j in 1..n: …n²n times n
i = 1; while i < n: i = i × 2log₂ ni doubles each time; it takes log₂ n doublings to reach n
Two loops one after the othern + n = 2n → O(n)Add, don't multiply
Loop of n whose body does a log n loopn log nMultiply nested costs

Step 2: drop constants and small terms

A program that takes 3n² + 10n + 7 steps is O(n²). When n = 1,000,000, the n² term is a trillion and the rest barely matters. So: keep only the biggest term and delete its constant multiplier.

Worked example

How many substrings can you form from a string of length m? Count by starting position: starting at position 1 there are m choices of end, starting at position 2 there are m−1, … down to 1. Total = m + (m−1) + … + 1 = m(m+1)/2, which is O(m²).

Worked example

Multiplying an m × n matrix by an n × p matrix. The result has m·p cells. Each cell is a sum of n products. Total work = m · p · n = O(m·n·p).

Worked example

A truth table with n variables has one row for every combination of 0/1 values. Two choices per variable, n variables: 2 × 2 × … × 2 = 2ⁿ rows.

Step 3: the ladder of growth rates

1 < log n < √n < n < n log n < n^1.5 < n² < n³ < n^(log n) < 2ⁿ < n! < nⁿ

To get a feel, here is what each means for n = 1,000:

How to compare two weird functions

When two functions are hard to compare, take the logarithm of both (a larger function has a larger log).

Worked example: where does n^(log n) sit?
  1. log(n^(log n)) = (log n) · (log n) = (log n)².
  2. log(n²) = 2 log n. Since (log n)² beats 2 log n for large n, n^(log n) is bigger than n².
  3. The same holds for every nᶜ (c a constant): (log n)² beats c·log n.
  4. log(2ⁿ) = n. And n beats (log n)². So 2ⁿ is bigger than n^(log n).

Conclusion: any polynomial < n^(log n) < 2ⁿ.

Common mistake: thinking n^(log n) is exponential. It is slower-growing than 2ⁿ. And n log n is smaller than n^1.5, because log n grows slower than any power of n, even n^0.5.

Step 4: recurrences (recursive algorithms)

A recursive algorithm's cost is written as an equation about itself. For example, binary search checks the middle and then searches one half: T(n) = T(n/2) + 1. That halves n each time, so it takes log₂ n steps. Merge sort sorts two halves and then merges them in n steps: T(n) = 2T(n/2) + n, which gives n log n.

Master theorem for T(n) = a·T(n/b) + nᵈ (a pieces, each of size n/b, plus nᵈ work to combine). Compare d with log_b(a):

• d > log_b a → nᵈ (combining dominates)
• d = log_b a → nᵈ log n (balanced)
• d < log_b a → n^(log_b a) (the pieces dominate)

Merge sort: a = 2, b = 2, d = 1, log₂ 2 = 1, so d equals it → n¹ log n. Binary search: a = 1, b = 2, d = 0, log₂ 1 = 0, equal → n⁰ log n = log n.

Best, worst and average case

The same algorithm can be fast on lucky input and slow on unlucky input. Worst case is the guarantee. Example: quicksort is O(n log n) on average but O(n²) if the pivot is always the smallest or largest element (e.g. already sorted input and a bad pivot rule). Space complexity counts extra memory the same way.

Check yourself

ISRO 2023 · Q24

The asymptotic complexity of four functions are f1(n) = 2ⁿ, f2(n) = n^(3/2), f3(n) = n log n, f4(n) = n^(log n). Arrange in increasing order of complexity.

f3, f2, f4, f1. n log n is below n^1.5 (a log is smaller than n^0.5). n^1.5 is polynomial, so it is below n^(log n). And n^(log n) is below 2ⁿ (compare the logs: (log n)² versus n).

The complexity of matrix multiplication of two matrices A and B whose orders are m × n and n × p respectively is

m·p output cells, each needing n multiply-adds: O(m·n·p). The first option only counts the cells, not the work inside each.
ISRO 2023 · Q46

From a character string of length m, the number of substrings of all lengths that can be formed is

m + (m−1) + … + 1 = m(m+1)/2 (counting substrings by their start and end positions).
ISRO 2023 · Q47

A truth table will need how many rows if there are n variables?

Each variable doubles the number of combinations: 2ⁿ.
