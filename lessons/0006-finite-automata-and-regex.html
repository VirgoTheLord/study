6 · Finite Automata & Regular Expressions

Module B · Theory of computationAsked in 2023 and 2025 Machines that read strings, and the patterns they accept.

Start here: what are we even doing?

An alphabet (Σ) is a set of symbols, e.g. {a, b} or {0, 1}. A string is a sequence of symbols (abba). A language is a set of strings, e.g. "all strings that end in b". The central question of this subject: what kinds of languages can a machine recognise, and how powerful must the machine be?

The simplest machine is a finite automaton: a tiny machine with a fixed number of states and no memory other than "which state am I in." It reads the string one symbol at a time, hopping between states, and at the end says yes (accept) or no (reject).

DFA: the deterministic finite automaton

A DFA has: a finite set of states, a start state (drawn with a small incoming arrow), some final (accepting) states (drawn as double circles), and a transition for every (state, symbol) pair. "Deterministic" means exactly one move is possible each time.

Trace it

Input abab: start E → (a) O → (b) O → (a) E → (b) E. It ends in the final state E: accepted (two a's, an even number). Input aba: E → O → O → E: accepted (two a's). Input ab: E → O → O: ends in O, so rejected (one a).

How to design one

Ask: "what do I need to remember about what I've read so far?" Each answer becomes a state. For "ends in b" you need to remember only whether the last symbol was b. For "even number of a's" you remember parity. For "contains ab" you remember how far you are into matching "ab".

NFA: the non-deterministic version

An NFA may have several moves for the same symbol (or none), and may have ε-transitions (moves that consume no input). It accepts if some path leads to a final state. NFAs look easier to design but are no more powerful: every NFA can be converted to a DFA that accepts the same language.

Converting an NFA to a DFA (subset construction)

Each DFA state is a set of NFA states ("where might the NFA be right now?"). An NFA with n states can need up to 2ⁿ DFA states.

Worked example: strings ending in ab

NFA: q0 loops on a and b; q0 –a→ q1; q1 –b→ q2 (final). Build the DFA:

  1. Start: {q0}. On a: q0 can stay at q0 or go to q1 → {q0,q1}. On b: {q0}.
  2. {q0,q1}: on a → {q0,q1}. On b → q0 stays, q1 goes to q2 → {q0,q2}.
  3. {q0,q2}: on a → {q0,q1}. On b → {q0}.
  4. Final DFA states are those containing q2: {q0,q2}. So the DFA has 3 states.

Minimising a DFA

Two states are equivalent if they behave identically from now on. Merge equivalent states to get the smallest DFA.

  1. Delete unreachable states.
  2. Split states into two groups: final and non-final.
  3. Look at each group: if two states in it send some symbol to different groups, split them apart. Repeat until no group can be split.
  4. Each remaining group becomes one state.
Worked example

States 1,2,3,4; finals {3,4}. On a: every state goes to 2. On b: 1→3, 2→4, 3→3, 4→4. Groups: {1,2} (non-final), {3,4} (final). Check 1 vs 2: on a both go to 2 (group {1,2}); on b they go to 3 and 4 (both in group {3,4}). Same → equivalent. Check 3 vs 4 similarly: equivalent. Minimal DFA = 2 states. (The language is "ends in b".)

Regular expressions

A regular expression is a compact pattern that describes a language. Building blocks:

PatternMeaning
aThe single string "a"
r + s (or r | s)Either r or s
r sr followed by s
r*Zero or more repetitions of r
r+ (in programming regex)One or more repetitions
[0-9]Any one character in the set

Regular languages are exactly the languages accepted by DFAs, by NFAs, and described by regular expressions. Examples:

  • Strings that end in b: (a+b)*b. Start with a: a(a+b)*. Contain "ab": (a+b)*ab(a+b)*.
  • An identifier (variable name): letter (letter | digit)*. It must start with a letter, then anything.
  • A hex constant: 0x[0-9A-F]+ means the characters 0x followed by one or more hex digits (uppercase letters only!).

Identities worth knowing: (a*)* = a*   a*a* = a*   (a+b)* = (a*b*)* = (a*+b*)*   ε + aa* = a*   (a*b)* + (b*a)* = (a+b)*

Why (a*b)* + (b*a)* = (a+b)*

(a*b)* produces ε or any string whose last symbol is b. (b*a)* produces ε or any string whose last symbol is a. Any non-empty string over {a,b} ends in a or b, and the empty string is in both. So together they give every string, which is (a+b)*.

Check yourself

ISRO 2025 · Q78

Consider the regular expression R over the alphabet {a, b}: (a*b)* + (b*a)*. Which of the following describes the same language as R?

(a+b)*: see the explanation above. The other options cannot produce strings like "abab" (a*b* + b*a* only allows at most one switch between a's and b's).
ISRO 2025 · Q28

Which of the following hexadecimal constants match the regular expression (0x[0-9A-F]+)?

0x4C5: starts with 0x, then digits 4, C, 5 all in [0-9A-F] ✓. 0x50b has a lowercase b, not in the set. 04A has no "x". "0x" has no digit after it, but + needs at least one.
ISRO 2023 · Q7

An NFA with ε-transitions is meant to accept strings corresponding to a lexical token id (an identifier), with tokens letter = [a-zA-Z] and digit = [0-9]. Which extended regular expression corresponds to the token id?

An identifier starts with a letter and continues with any mix of letters and digits. The last option is wrong because (letter* | digit*) cannot mix: it would reject "a1b".
