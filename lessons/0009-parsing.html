9 · Parsing

Module B · CompilersAsked in 2023 and 2025 Top-down vs bottom-up, LL(1), ambiguity, shift-reduce.

Start here

The parser's job: decide whether a token string follows the grammar, and show how (the parse tree). There are two basic strategies, and the names describe the direction in which the parse tree is built.

Derivations and ambiguity

Use the grammar E → E + E | E × E | id and the input id + id × id. There are two completely different trees:

A grammar is ambiguous if some string has more than one parse tree, which is the same as having more than one leftmost derivation, and the same as having more than one rightmost derivation. (A leftmost and a rightmost derivation of the same tree are always different sequences, so that difference alone doesn't show ambiguity.)

Ambiguity is a problem because the meaning of the program becomes unclear (is 2+3×4 equal to 14 or 20?). Fix it by rewriting the grammar to encode precedence: E → E + T | T, T → T × F | F, F → id. Now × is deeper in the tree, so it is done first.

Top-down parsing and LL(1)

LL(1): the first L means scan the input from Left to right; the second L means produce a Leftmost derivation; 1 means look at only one input symbol ahead to decide which rule to use. LL(1) parsers never backtrack.

For a grammar to be LL(1), the parser must always be able to choose the right production by peeking at one token. Two things get in the way:

  • Left recursion (A → A α) makes a top-down parser loop forever. Remove it.
  • Common prefixes (A → ab | ac) make the choice unclear. Fix by left factoring: A → a A′, A′ → b | c.
  • An ambiguous grammar is never LL(1).

FIRST and FOLLOW

FIRST(X) = the set of terminals that can begin a string derived from X (include ε if X can vanish). FOLLOW(A) = the set of terminals that can appear immediately after A in some derivation (and $, end-of-input, if A can end the string).

Worked example

Grammar: S → A B; A → a | ε; B → b.

  1. FIRST(A) = {a, ε}. FIRST(B) = {b}.
  2. FIRST(S): S starts with A; A can be a, or vanish and let B start, so FIRST(S) = {a, b}.
  3. FOLLOW(S) = {$}. FOLLOW(A) = what follows A in S → A B, which is FIRST(B) = {b}. FOLLOW(B) = FOLLOW(S) = {$}.

The parsing table says: when expanding A, if the next token is a use A → a; if it is in FOLLOW(A) (b), use A → ε. Each table cell has at most one rule, so the grammar is LL(1).

Bottom-up parsing (shift-reduce)

A bottom-up parser keeps a stack. It shifts the next input token onto the stack, and when the top of the stack matches the right side of a rule it reduces it to the left side. It finds a rightmost derivation but in reverse. When the input is consumed and only the start symbol is left, it accepts.

The LR family, from weakest to strongest: LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ CLR(1). yacc generates LALR(1) parsers. Every LL(1) grammar is also LR(1), so bottom-up parsers handle more grammars. Conflicts (shift/reduce, reduce/reduce) arise when the table can't decide.

Check yourself

ISRO 2023 · Q8

Consider the context-free grammar G E → E + E | E × E | id. Which statement is TRUE?

Exactly two: id + (id × id) and (id + id) × id. With two operators there are only two ways to choose which one is applied last.
ISRO 2023 · Q11

In the context of parsing techniques, LL(1) refers to:

LL(1): Left-to-right scan, Leftmost derivation, 1 lookahead symbol, no backtracking.
ISRO 2025 · Q32

For the same input string, which of the following options is true in the case of an ambiguous grammar? (i) two different parse trees (ii) two leftmost derivations (iii) two rightmost derivations (iv) leftmost and rightmost derivations are different

Ambiguity means two parse trees, two leftmost derivations and two rightmost derivations. Statement (iv) is not a symptom of ambiguity, since a leftmost and a rightmost derivation always differ in order.
Practice (written by me)

Which statement about LR(1) and LL(1) is correct?

LR(1) accepts a strictly larger class, so every LL(1) grammar is LR(1) but not the reverse. LL parsers are top-down and cannot handle left recursion.
