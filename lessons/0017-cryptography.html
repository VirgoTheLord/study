17 · Cryptography

Module E · SecurityAsked in 2023 and 2025 Security goals, symmetric and public-key encryption, RSA, hashes and signatures.

Start here: what is security trying to achieve?

GoalIn plain words
ConfidentialityOnly the right people can read it (protection from unauthorised disclosure)
IntegrityIt arrives exactly as it was sent; nobody altered it
AvailabilityThe service works when you need it
AuthenticationYou are who you say you are
Non-repudiationThe sender cannot later deny having sent it
Access controlOnly authorised people may use a resource

Cryptography is the toolbox: turn readable plaintext into unreadable ciphertext using a key (encryption), and back again (decryption).

Symmetric-key cryptography

Sender and receiver share one secret key, used both to lock and unlock. Fast, so used for bulk data. Examples: DES (56-bit key, now weak), 3DES, AES (128-bit blocks, keys of 128, 192 or 256 bits), plus stream ciphers like RC4.

  • Key space: an n-bit key has 2ⁿ possible values. Each extra bit doubles the number of keys an attacker must try.
  • The key-distribution problem: how do two strangers agree on a secret key over an open network? And if every pair of n people needs a unique key, you need n(n−1)/2 keys (one per pair). For 16 persons: 16 × 15 / 2 = 120 keys.

Public-key (asymmetric) cryptography

Each person has a key pair: a public key (shared openly) and a private key (kept secret). What one key locks, only the other unlocks.

  • Confidentiality: encrypt with the receiver's public key; only their private key decrypts.
  • Authentication / digital signature: encrypt (sign) with your private key; anyone can check with your public key. This also gives non-repudiation.
  • It needs only 2n keys for n people, solving the distribution problem, but it is much slower than symmetric encryption. So in practice it is used to exchange a symmetric key and for signatures. It does not help against denial-of-service attacks.
  • Algorithms: RSA, ECC, ElGamal; Diffie–Hellman is for key exchange.

RSA step by step

  1. Pick two primes p and q. Compute n = p × q.
  2. Compute φ(n) = (p − 1)(q − 1).
  3. Pick public exponent e with gcd(e, φ) = 1.
  4. Find private exponent d with e × d ≡ 1 (mod φ).
  5. Public key = (e, n). Private key = (d, n). Encrypt: c = mᵉ mod n. Decrypt: m = cᵈ mod n.
Worked example (2025 question)

p = 11, q = 13, d = 7. n = 143, φ = 10 × 12 = 120. We need e with e × 7 ≡ 1 (mod 120), i.e. e × 7 = 1 + 120k. Try k = 6: 721 = 7 × 103, so e = 103. Check the other options: 143 × 7 = 1001 = 8 × 120 + 41 ✗; 21 × 7 = 147 = 120 + 27 ✗; 19 × 7 = 133 = 120 + 13 ✗.

Tiny RSA in action

p = 3, q = 11: n = 33, φ = 20. Pick e = 3; d = 7 (3 × 7 = 21 ≡ 1 mod 20). Encrypt m = 4: c = 4³ mod 33 = 64 mod 33 = 31. Decrypt: 31⁷ mod 33 = 4 ✓.

Hashes, MACs, signatures, certificates

ToolWhat it doesKey?
Hash / message digest (SHA-256, MD5)Turns any message into a fixed-size fingerprint; one-way; any change flips the fingerprint. Gives integrity checks.No key
MAC / HMACA hash computed with a shared secret key: integrity and authenticityShared key
Digital signatureHash the message, then encrypt the hash with the sender's private keyPrivate key
Digital certificateA document binding a public key to an identity, signed by a Certificate Authority (CA)

PKI (public key infrastructure) is the system of CAs and certificates that lets you trust public keys. The standard certificate format is X.509. (X.25 is an old packet-switching protocol; IEEE 802.11 is Wi-Fi; 802.3 is Ethernet.)

Check yourself

ISRO 2025 · Q38

An RSA crypto system selects two primes p = 11 and q = 13. If the private key is d = 7, which of the following can be the value of the public key e?

φ = 120; e × 7 ≡ 1 (mod 120) gives e = 103 (7 × 103 = 721 = 6 × 120 + 1).
ISRO 2025 · Q8

How many keys are needed for encrypted communication among 16 persons using AES encryption assuming a unique key is used between any two persons?

One key per pair: 16 × 15 ÷ 2 = 120.
ISRO 2025 · Q9

Which of the following does not use key(s)?

A plain hash is keyless. A MAC needs a key; ciphers and key exchange use keys.

It gives confidentiality, authentication (signatures) and key exchange, but encryption by itself doesn't stop DoS.
