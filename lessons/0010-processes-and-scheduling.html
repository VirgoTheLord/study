10 · Processes, Threads & CPU Scheduling

Module C · Operating systemsAsked in 2023 and 2025 What a process is, its states, threads, schedulers, and the scheduling formulas.

Start here: what does an operating system do?

The operating system (OS) sits between programs and hardware. It shares one CPU and one memory among many programs, protects them from each other, and gives them services (files, networking). The central idea: although there may be only one CPU, the OS switches between programs so quickly that they appear to run at the same time. This lesson is about how that switching is organised.

Process

A program is a file on disk. A process is a program in execution: its code, its current position (program counter), its data, its stack, and its allocated resources. The OS keeps a record for each process called the PCB (process control block): process id, state, registers, memory info, open files.

Processes are created with calls like fork(): the creating process is the parent; the new one is the child. After creation the parent may keep running concurrently with the child, or it may wait() until some or all of its children finish. (Both are possible.)

Process states

A context switch saves the state of the running process in its PCB and loads the state of the next one. It is pure overhead: no useful work happens during it.

Threads

A thread is a lightweight unit of execution inside a process. Threads of one process share its code, data and open files but each has its own program counter and stack. Creating and switching threads is cheaper than for processes. Two kinds: user threads (managed by a library) and kernel threads (managed by the OS). How they map:

ModelMeaningNote
Many-to-oneMany user threads → one kernel threadOne blocking call blocks all
One-to-oneEach user thread → its own kernel threadLinux and Windows
Many-to-manyMany user threads → many kernel threadsFlexible, complex

Interrupts, traps and system calls

  • An interrupt is a signal that makes the CPU pause its current work and run a handler. Hardware interrupts come from devices (via the system bus); software interrupts are triggered by instructions such as system calls.
  • A trap (exception) is a software-generated interrupt caused by the running program: a divide by zero, an illegal memory access, or a system call. So the statement "a trap is a hardware-generated interrupt" is false.
  • If a process tries to access memory belonging to the OS or to another user's process, the hardware detects the violation and traps to the OS, which typically terminates the process.
  • CPU modes: user mode for programs, kernel mode for the OS; a system call switches into kernel mode.

The three schedulers

SchedulerJobRuns
Long-term (job scheduler)Chooses which jobs to load into memory; controls the degree of multiprogrammingRarely
Medium-termSwaps processes out of memory and back in (swapping)Occasionally
Short-term (CPU scheduler)Picks which ready process gets the CPU nextVery often, so it must be very fast

CPU scheduling: algorithms and the formulas

For each process we know the arrival time (AT) and burst time (BT, the CPU time it needs). The measures:

Completion time (CT) = when it finishes
Turnaround time (TAT) = CT − AT (total time in the system)
Waiting time (WT) = TAT − BT (time spent in the ready queue)
Response time = time of first CPU use − AT

Worked example: FCFS with an out-of-order list (2025 question)

P1: AT 6, BT 24. P2: AT 0, BT 3. P3: AT 3, BT 3. Always sort by arrival time first.

  1. Order by arrival: P2 (0), P3 (3), P1 (6).
  2. Gantt chart: P2 runs 0–3, P3 runs 3–6, P1 runs 6–30.
  3. Completion times: P2 = 3, P3 = 6, P1 = 30.
  4. Turnaround = CT − AT: P2 = 3, P3 = 3, P1 = 24. Average = 30/3 = 10.
  5. Waiting = TAT − BT: 0, 0, 0. Average = 0.
Worked example: FCFS vs SJF

P1 (AT 0, BT 5), P2 (AT 1, BT 3), P3 (AT 2, BT 1).

FCFS: P1 0–5, P2 5–8, P3 8–9. Waiting: 0, 4, 6 → average 3.33.

SJF (non-preemptive): at time 0 only P1 is there, so it runs 0–5. Then the shortest is P3: 5–6, then P2: 6–9. Waiting: P1 0, P3 3, P2 5 → average 2.67. SJF gives the smaller average waiting time.

Which of the following transitions is not possible between the process states?

Both behaviours are allowed. The wait is done with wait(), not signal().
