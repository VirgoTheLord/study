19 · The Relational Model, ER Diagrams & SQL

Module F · DatabasesAsked in 2023 and 2025 Tables and keys, turning an ER diagram into tables, and the SQL you need.

Start here

A database stores organised data; a DBMS (database management system) is the software that manages it. In the relational model data lives in tables (called relations). A table has columns (attributes) and rows (tuples). Example, a student table:

1Asha10
2Ravi20

Keys

KeyMeaning
Super keyAny set of attributes that uniquely identifies a row
Candidate keyA minimal super key (remove any attribute and it stops being unique)
Primary keyThe candidate key you choose as the main identifier (no NULLs, no duplicates)
Foreign keyAttributes in one table that refer to the primary key of another, linking the tables (here dept_id refers to the department table)

ER diagrams and how to turn them into tables

An entity-relationship (ER) diagram is a picture used to design a database: entities (things: Student, Course), attributes (their properties) and relationships between them (Student enrols in Course) with a cardinality: one-to-one (1:1), one-to-many (1:N), many-to-many (M:N). The ER model shows the static structure of the data (not behaviour or processes).

Conversion rules
• Each entity becomes a table.
• 1:N: put the foreign key on the "many" side; no new table.
• M:N: create a new junction table holding the keys of both entities.
• 1:1: put the foreign key on either side (or merge the tables).

Worked example: Authors and Books

One author writes many books (1:N). So the foreign key author_id goes in the books table. Putting it in authors would need a list of books in one cell, which breaks the rule of atomic values.

Worked example (2025): count the tables

Entities A and B. R1 is one-to-many from A to B: it is stored as a foreign key in B, no extra table. R2 is many-to-many: needs a junction table. Tables: A, B, R2 = 3.

SQL essentials

SELECT name, dept_id          -- which columns
FROM student                  -- which table
WHERE dept_id = 10            -- filter rows
ORDER BY name;                -- sort

INSERT INTO student VALUES (3, 'Meera', 10);
UPDATE student SET dept_id = 20 WHERE roll_no = 3;
DELETE FROM student WHERE roll_no = 3;

Joins: combining tables

  • Cross join (Cartesian product): every row of R paired with every row of S. If R has 3 rows and S has 4 you get 12 rows. SELECT * FROM R, S (with no WHERE) is a cross join.
  • Inner join: only the pairs that satisfy the join condition: SELECT * FROM student s JOIN dept d ON s.dept_id = d.dept_id.
  • Natural join: inner join on all same-named columns.
  • Outer joins (left/right/full): also keep unmatched rows, filling the gaps with NULL.

Grouping and aggregation

SELECT dept_id, COUNT(*), AVG(marks)
FROM student
GROUP BY dept_id
HAVING COUNT(*) > 5;   -- HAVING filters groups; WHERE filters rows

Subqueries

A query inside a query. To delete all teachers whose department is in the CSE building:

DELETE FROM teacher
WHERE dept_name IN (SELECT dept_name FROM department
                    WHERE building = 'CSE');

(You cannot write dept_name IN 'CSE'; the building lives in the other table, so a subquery is needed.)

Views

A view is a saved query that acts like a virtual table: CREATE VIEW cse_students AS SELECT name FROM student WHERE dept_id = 10;. It can be queried like a normal table, normally does not keep a duplicate copy of the data, and is useful for restricting access to sensitive columns. Simple views can be updated; complex ones (with joins or aggregates) often cannot.

Worked example (2023 puzzle): reading what a sequence of inserts does

Table T(X, Y) starts with (1, 1). Then 128 times we insert (MX+1, 2·MY+1), where MX, MY are the current maxima. Rows: X=1,Y=1; X=2,Y=3; X=3,Y=7; X=4,Y=15; X=5,Y=31; X=6,Y=63; X=7,Y=127. Y follows 2ˣ − 1. For X = 7 the answer is 127.

Which SQL query deletes all tuples in the teacher relation for those teachers associated with a department located in the building named CSE (building is in the department relation)?

The subquery finds the departments in CSE; the outer query deletes the teachers of those departments from the correct table.
ISRO 2023 · Q30

Table T has columns X and Y. One record (X=1, Y=1) is inserted. Then, 128 times, a new record is inserted with X = MX+1 and Y = 2×MY+1 (MX, MY being the maxima at that moment). What is the output of SELECT Y FROM T WHERE X=7?

Y = 2ˣ − 1, so X = 7 gives 127.
ISRO 2025 · Q44

Assume a one-to-many relationship from table "authors" to table "books". Where should the foreign key reside in an optimal design?

The "many" side holds the foreign key.
ISRO 2025 · Q46

A and B are two entities in an E-R diagram with simple single-value attributes. R1 is a one-to-many relationship from A to B; R2 is a many-to-many relationship from A to B. What is the minimum number of tables required to represent A, B, R1 and R2 in the relational model?

A, B, and the junction table for R2. R1 is just a foreign key in B.
