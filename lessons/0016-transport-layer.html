16 · Transport Layer, TCP & Window Sizing

Module D · Computer networksAsked in 2023 and 2025 TCP vs UDP, reliability, congestion control, and the bandwidth–delay calculation.

Start here

IP gets packets to the right computer but makes no promises: packets may be lost, duplicated or arrive out of order. The transport layer delivers data to the right program on that computer, identified by a port number (e.g. 80 = web, 25 = mail, 53 = DNS), and can add reliability on top.

TCP in four ideas

  1. Three-way handshake to open a connection: client sends SYN, server replies SYN-ACK, client sends ACK.
  2. Acknowledgements and retransmission: every segment has a sequence number; the receiver ACKs what it got; the sender resends anything not ACKed in time.
  3. Flow control: the receiver advertises its free buffer space (the window) so a fast sender can't overwhelm a slow receiver.
  4. Congestion control: the sender limits itself to avoid overloading the network.

Congestion control

The sender maintains a congestion window (cwnd). Slow start: begin at 1 segment and double cwnd every round trip until a threshold (exponential growth, despite the name). Then congestion avoidance: grow by 1 segment per round trip (additive increase). On loss, cut the window (multiplicative decrease, often halving). Together: AIMD.

How big should the window be? (the key calculation)

Picture a pipe. The sender pushes packets in; the first ACK returns one round-trip time (RTT) after the first packet left. To keep the pipe full, the sender must have sent enough packets to cover that whole RTT before the first ACK arrives.

Bandwidth–delay product (BDP) = bandwidth × RTT = the number of bits "in flight" when the pipe is full.
Window needed for full utilisation = BDP (in bits, bytes or packets).
Utilisation with window W packets = W × Tt / (Tt + RTT), capped at 1, where Tt = packet size ÷ bandwidth. (This is also W ÷ (1 + RTT/Tt).)

Worked example (2025 question): TCP window to fill a link

Bandwidth 8,192,000 bits/s, latency 32 ms. Take latency as the round-trip time. BDP = 8,192,000 × 0.032 = 262,144 bits. In bytes: 262,144 ÷ 8 = 32,768 bytes. (If the 32 ms were one-way, the RTT would be 64 ms and the answer 65,536 bytes: the question says "latency", and 32,768 is the usual reading.)

Worked example (2023 question): utilisation above 96%

Link 1 Gbps, RTT 25 ms, packets of 1000 bytes. Ignore ACK size.

  1. Tt = 1000 × 8 bits ÷ 10⁹ bps = 8 µs.
  2. RTT ÷ Tt = 25 ms ÷ 8 µs = 25,000 µs ÷ 8 µs = 3125.
  3. Utilisation = W ÷ (1 + 3125) = W ÷ 3126.
  4. Need W ÷ 3126 > 0.96, so W > 3001.
  5. Options: 2000, 2400, 3000, 4000. 3000 gives 95.97%, just under 96%. So 4000 packets.

Stop-and-wait is the special case W = 1: utilisation = Tt ÷ (Tt + RTT), terrible on long fast links (here 8 µs ÷ 25.008 ms ≈ 0.03%).

Check yourself

ISRO 2023 · Q12

A host in one organisation is connected to another host using a 1 Gbps link with 25 ms RTT. The packet size is tuned to 1000 bytes. To have channel utilisation > 96%, how big should the window size be (in packets), assuming ACK packets have no impact?

W/3126 > 0.96 → W > 3001. Only 4000 qualifies.
ISRO 2025 · Q40

What is the ideal TCP window size of a sender to fully utilize a link of bandwidth 8192000 bps and latency of 32 ms?

BDP = 8,192,000 × 0.032 / 8 = 32,768 bytes (treating latency as the round-trip time).
Practice (written by me)

In TCP slow start, if cwnd is 4 segments now, what will it be after one more round trip without loss?

Slow start doubles cwnd each round trip: 4 → 8.
